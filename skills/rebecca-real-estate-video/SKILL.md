# Rebecca 高雄房產短影音

為 Rebecca 的高雄房產內容剪輯短影音。本 Skill 建立在 `video-use` 之上：
剪輯管線（轉錄、切點、渲染、字幕）遵循 `~/.claude/skills/video-use/SKILL.md`
的 Hard Rules；動畫與資訊圖卡可用 Remotion（參考 `remotion-create`、
`remotion-markup`、`remotion-render`、`remotion-captions`、
`remotion-best-practices` skills）或 PIL/ffmpeg。

本文件的規則分兩層：**硬性規則（不可違反）** 與 **風格指引（預設值，可依素材調整）**。

## 影片規格（硬性）

| 項目 | 規格 |
|------|------|
| 長度 | 45–60 秒 |
| 比例 / 解析度 | 9:16，1080×1920 |
| 幀率 | 30fps |
| 語言 | 繁體中文（台灣用語） |

## 硬性規則 — 事實正確性（絕不妥協）

1. **不得改寫任何房產數據**：地址、價格、坪數、單價、建蔽率、容積率，
   必須與來源素材或使用者提供的資料逐字一致。不確定就問，不得推算或四捨五入。
2. **都市計畫狀態照實陳述**：尚未核定的都市計畫，不得寫成「已核定」。
   用語必須反映實際狀態（例：「規劃中」「已公告尚未核定」「已核定」）。
3. **B-roll 不得張冠李戴**：找不到正確地點的 B-roll 時，改用資訊圖卡呈現，
   不得拿其他地點的畫面冒充。寧可用圖卡，不可用錯畫面。
4. **來源影片絕不修改、刪除或覆蓋**。所有輸出一律寫入 `<素材資料夾>/edit/`。

## 硬性規則 — 產出流程

5. **先 preview 後 final**：先輸出 `edit/preview.mp4` 給使用者確認；
   使用者明確同意後才渲染 `edit/final.mp4`。未經確認不得產出 final。
6. **剪輯策略先確認**：動手剪之前，用白話文描述剪輯策略（鉤子、結構、
   圖卡安排、B-roll 使用），等使用者同意。
7. **字幕不得遮住人臉**：渲染前用 `timeline_view.py` 抽查含人臉的段落，
   字幕與人臉重疊時調整 `MarginV` 或改用上方/側邊定位。preview 自檢
   必查此項。
8. **轉錄使用 ElevenLabs Scribe**（經 video-use 的 `transcribe.py`）。
   需要 `ELEVENLABS_API_KEY` 而尚未設定時，先向使用者索取；
   任何情況下不得在畫面、log 或 commit 中顯示完整 API Key。

## 內容結構（風格指引）

- **前 3 秒直接破題**：第一句就是最強賣點或最大反差
  （例：「XX 路三房，單價比周邊低 X 萬」）。不要用「大家好」開場。
- **每 4–7 秒一個視覺節拍**：字幕重點、B-roll 或資訊圖卡至少其一出現，
  避免任何超過 7 秒的靜態談話畫面。
- 建議結構：**鉤子（0–3s）→ 物件概況（3–15s）→ 亮點/數據（15–40s）→
  區域行情或都計題材（40–52s）→ 結尾 CTA（52–60s）**。可依素材調整。
- 結尾 CTA 保留給 Rebecca 的聯絡方式／追蹤引導。

## 品牌視覺（風格指引）

品牌色（預設 hex，可依 Rebecca 提供的正式色票更新）：

| 名稱 | Hex | 用途 |
|------|-----|------|
| 奶茶米色 | `#D8C3A5` | 圖卡背景、色塊 |
| 乾燥玫瑰粉 | `#C48793` | 次要強調、標題裝飾 |
| 香檳金 | `#D4B896` | **關鍵數字重點色**、邊框、icon |
| 暖象牙 | `#FAF3E8` | 主背景、字幕底色 |

- **關鍵數字（價格、坪數、單價等）一律使用重點色**（預設香檳金，
  深色背景上可加粗或放大），讓數據一眼可見。
- 字幕：繁中無襯線字體（Noto Sans TC 或系統可用之繁中字體），
  白字深邊或暖象牙底色塊，一行 8–12 字，斷在自然語氣處。
- 資訊圖卡：品牌色系、留白 ≥ 35%、一張卡只講一件事
  （一個數據或一個賣點），停留 ≥ 3 秒且配合口白節奏。

## 工作流程

1. **盤點素材**：`ffprobe` 每個來源檔；確認使用者提供的物件資料
   （地址、價格、坪數等以文字提供者為準）。
2. **轉錄**：`video-use` 的 `transcribe_batch.py` → `pack_transcripts.py`。
   （需 `ELEVENLABS_API_KEY`；會產生費用，第一次執行前告知使用者。）
3. **提案**：破題句、結構、圖卡清單、B-roll 對應表（無正確 B-roll 的
   點位標記為「改用圖卡」）。**等待確認。**
4. **執行**：EDL → 圖卡/動畫（Remotion 或 PIL，並行 sub-agent）→
   `render.py --preview` 產出 `preview.mp4`。
5. **自檢**（video-use 自檢流程，外加）：字幕是否遮臉、關鍵數字是否用
   重點色、所有數據與來源逐字核對、長度 45–60 秒、1080×1920@30fps。
6. **交付 preview**，收集回饋，確認後才 `render.py` 輸出 `final.mp4`。
7. **記錄**：附加至 `edit/project.md`（本次策略、數據核對結果、待辦）。

## 素材放置

使用者將原始影片放入任一資料夾（建議 `~/videos/<物件名>/`），
在該資料夾啟動剪輯。所有輸出進入該資料夾的 `edit/` 子目錄，
原始檔永不更動。
